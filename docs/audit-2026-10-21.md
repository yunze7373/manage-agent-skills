## 新增 audit 能力

```text
python skills/manage-agent-skills/scripts/skillctl.py --platform all audit --json
python skills/manage-agent-skills/scripts/skillctl.py --platform codex audit --strict
```

JSON 包含 schema_version、evidence_scope、findings、skills 和 severity summary。
检查前置元数据格式、名称可移植性、描述长度、目录名差异、重复标识、未知状态、
Codex 失效路径/名称规则/管理块、额外项目配置和 Antigravity 停放冲突。
普通模式仅 error 非零；strict 也将 warning 视为失败，info 不导致失败。

audit 是本地确定性检查，不自动联网追踪每个技能正文的时效，也不执行被发现技能的脚本。
要判断某个技能内容是否过时，仍须按它的具体主题核实权威来源。

## 设计取舍与迁移

1. **兼容性优先**：Codex 路径规则作为默认，名称规则作为显式宿主能力保留。
   现有名称规则不自动删除；默认 reconcile 不会再把路径迁为名称。
2. **保留用户选择**：Antigravity 默认继续指向原 App 根，CLI 用户显式选择 surface；
   避免升级后同一条旧命令无提示地操作另一套技能。
3. **恢复证据优先**：保留备份历史，不做自动清理；预设尽量预检，但不假装拥有宿主事务。
4. **有界依赖**：复用仓库已有 PyYAML，将其要求从 Hermes 扩展到 metadata 读取；不增加常驻服务或新运行时依赖。
5. **真实宿主是最终依据**：配置成功、目录移动成功、重启成功、提示词验证是不同证据层。

示例迁移：

```text
# 默认官方路径模式
python <skillctl> --platform codex disable demo --dry-run
# 确认具体宿主支持 name 后才选用
python <skillctl> --platform codex --codex-selector name reconcile --dry-run
# 当前 agy CLI 全局根
python <skillctl> --platform antigravity --antigravity-surface cli status
```
